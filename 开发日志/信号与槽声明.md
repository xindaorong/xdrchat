# Qt 信号与槽 — 完整指南

基于本项目的实际代码，覆盖从声明、连接到分发、MOC 机制的完整知识。

---

## 一、头文件中的三块区域

```cpp
class LoginDialog : public QDialog
{
    Q_OBJECT          // ← ① 必须有，否则 MOC 不会处理

public:
    // 普通构造函数、成员函数

signals:             // ← ② 信号声明区（只声明，不实现）
    void switchRegister();

private slots:       // ← ③ 槽函数声明区（声明 + .cpp 里写函数体）
    void on_login_btn_clicked();

private:
    // 普通成员变量（如 UI 指针、_handlers 等）
};
```

## 二、信号（signals）详解

### 2.1 声明规则

```cpp
signals:
    void switchRegister();                  // 无参数
    void switchReset();                     // 无参数
    void sig_connect_tcp(ServerInfo);       // 带自定义类型参数
```

| 规则 | 说明 |
|---|---|
| 只写声明，不写实现 | `.cpp` 里绝对不能写函数体，MOC 自动生成 `.moc` 文件里的实现 |
| 返回类型必须是 `void` | 信号不能有返回值 |
| 参数类型和个数任意 | 需要注册元类型（`Q_DECLARE_METATYPE`）的自定义类型也行 |
| 默认访问权限 | `signals:` 等价于 `protected signals:`，但习惯写在 public 下面 |

### 2.2 信号是"发什么"，不是"怎么办"

信号不包含任何业务逻辑，只负责**通知**：

```cpp
// LoginDialog 声明：我能通知外界两件事
signals:
    void switchRegister();   // "用户想注册"
    void switchReset();      // "用户想重置密码"
```

**谁接收、接收后做什么，LoginDialog 完全不知道也不关心**——这就是解耦。

## 三、槽（slots）详解

### 3.1 声明

```cpp
public slots:        // 任何外部代码都能 connect 和直接调用
    void SlotSwitchReg();

private slots:       // 仅类内部使用（你的项目中最常见）
    void on_return_btn_clicked();
    void slot_reset_mod_finish(ReqId id, QString res, ErrorCodes err);
```

### 3.2 槽就是普通成员函数

```cpp
// .h 里声明
private slots:
    void slot_forget_pwd();

// .cpp 里正常写实现（和普通函数一模一样）
void LoginDialog::slot_forget_pwd()
{
    qDebug() << "slot forget pwd";
    emit switchReset();   // 槽内部也可以 emit 信号
}
```

唯一的区别：槽可以被 `connect` 连接，普通函数不行。

## 四、信号 vs 槽 vs 普通函数 对比

```
            声明关键字       需要实现      返回类型      能被connect    默认访问权限
─────────────────────────────────────────────────────────────────────────────
信号     │  signals:     │  ❌ 不用    │  必须 void  │  ✅ 能发出   │ protected
槽       │  slots:       │  ✅ 需要    │  任意       │  ✅ 能接收   │ private(按写的位置)
普通函数  │  无关键字     │  ✅ 需要    │  任意       │  ❌ 不能     │ private(按写的位置)
```

## 五、connect — 四两拨千斤

### 5.1 基础语法

```cpp
connect(发送者, &发送者类::信号名, 接收者, &接收者类::槽函数名);
```

### 5.2 本项目中的四种 connect 写法

#### 写法一：信号 ↔ 槽（跨对象通信）

```cpp
// 源文件: mainwindow.cpp:17
connect(_login_dlg, &LoginDialog::switchRegister, this, &MainWindow::SlotSwitchReg);
//       ↑ 发送者     ↑ 信号                      ↑ 接收者  ↑ 槽
```

这是最经典、最推荐的写法。编译期检查类型，写错立即报错。

#### 写法二：控件信号 → lambda（内联处理）

```cpp
// 源文件: registerdialog.cpp:38
connect(ui->user_edit, &QLineEdit::editingFinished, this, [this](){
    checkUserValid();
});
```

好处是逻辑紧邻、不用单独声明槽函数。`[this]` 捕获当前对象指针，使 lambda 内部能调用成员函数。

#### 写法三：按钮点击 → 直接转发信号

```cpp
// 源文件: logindialog.cpp:11
connect(ui->pushButton_2, &QPushButton::clicked, this, &LoginDialog::switchRegister);
//       ↑ 按钮             ↑ 点击信号           ↑ LoginDialog ↑ 信号（不是槽！）
```

**信号可以直接 connect 到另一个信号**，相当于转发：按钮点击 → `switchRegister` 信号发出 → MainWindow 收到。

#### 写法四：跨线程/跨模块信号 → 槽（网络回调）

```cpp
// 源文件: registerdialog.cpp:104
connect(HttpMgr::GetInstance().get(), &HttpMgr::sig_reg_mod_finish,
        this, &RegisterDialog::slot_reg_mod_finish);
```

`HttpMgr` 是单例，网络回包后通过信号通知 UI 层。UI 层只管展示，网络层只管通信，互不依赖。

## 六、自动连接 — Qt 命名约定

```cpp
// 槽函数命名: on_<控件objectName>_<信号名>
void on_return_btn_clicked();      // 控件名 return_btn  + clicked()
void on_varify_btn_clicked();      // 控件名 varify_btn  + clicked()
void on_sure_btn_clicked();        // 控件名 sure_btn    + clicked()
```

只要 `setupUi(this)` 被执行，Qt 的 `connectSlotsByName` 会**自动匹配**这些函数，**不需要手写 connect**。

前提条件：
1. 类必须包含 `Q_OBJECT` 宏
2. 控件 `objectName` 要和函数名中的控件名部分一致
3. 槽函数签名要和信号的参数匹配

## 七、emit — 发射信号

```cpp
// logindialog.cpp:20
void LoginDialog::slot_forget_pwd()
{
    qDebug() << "slot forget pwd";
    emit switchReset();   // ← 发射！所有 connect 到这个信号的槽都会被执行
}
```

`emit` 本质是一个空宏——编译后等于不存在。它纯粹是给人看的，表示"这里在发射信号"。

等价关系：
```cpp
emit switchReset();      // ← 给人看的
switchReset();           // ← 效果完全一样
```

但项目里永远写 `emit`，这是 Qt 社区的规范。

## 八、MOC — 幕后的魔法

```
你的 .h 文件（包含 signals:/slots: 和 Q_OBJECT）
        │
        ▼
  MOC 预处理 (Meta-Object Compiler)
        │
        ├── 为 signals: 里的函数生成实现体
        ├── 生成元对象信息（类名、信号列表、槽列表）
        ├── 生成 qt_metacall() 函数 → connect 的底层调用入口
        └── 输出  moc_xxx.cpp
                │
                ▼
         普通 C++ 编译器 (MSVC / GCC)
                │
                ▼
           最终可执行文件
```

**`signals:` 声明的函数不需要你写实现**，就是因为 MOC 替你生成了。忘记加 `Q_OBJECT` → MOC 不处理 → 链接报 `undefined reference`。

## 十、Q_OBJECT 宏与自定义类型注册

### 10.1 Q_OBJECT 是必须的

```cpp
class MyDialog : public QDialog
{
    Q_OBJECT   // ← 忘记加 → 编译期报 "undefined reference to vtable"
    // ...
};
```

这个宏展开后声明了：
- `metaObject()` — 返回类的元对象
- `qt_metacast()` — 运行时类型转换
- `qt_metacall()` — 信号/槽的索引调用入口
- `staticMetaObject` — 静态元对象

### 10.2 自定义类型作为信号参数

```cpp
// global.h 中注册自定义枚举，让信号槽能传这个类型
Q_DECLARE_METATYPE(ReqId)
Q_DECLARE_METATYPE(ErrorCode)
Q_DECLARE_METATYPE(Modules)
```

否则在跨线程的信号槽传自定义类型会失败。

## 十一、常见错误

```cpp
// ❌ 错误 1：信号写了实现（在 .cpp 里）
// void LoginDialog::switchRegister() { ... }
// → 链接报错：重复定义（MOC 已经生成了一份实现）

// ❌ 错误 2：信号返回类型不是 void
signals:
    int switchRegister();   // ❌

// ❌ 错误 3：忘了 Q_OBJECT
class LoginDialog : public QDialog
{
    // Q_OBJECT      ← 忘了！
signals:
    void switchRegister();
};
// → undefined reference to `vtable for LoginDialog`

// ❌ 错误 4：connect 信号和槽参数不匹配
connect(sender, &Sender::sig(int, QString), receiver, &Receiver::slot(int));
// → 信号有 2 个参数，槽只有 1 个 → 运行时 "No such slot" 警告

// ❌ 错误 5：lambda 捕获 this 后对象已销毁
connect(httpMgr, &HttpMgr::sig_finish, this, [this](){
    this->showTip(...);  // 如果 this 已 delete → 崩溃！
});
// → 确保接收者的生命周期 ≥ 信号的发送周期
```

## 十二、总结

```
┌──────────────────────────────────────────────────────┐
│                   Qt 程序的运行方式                    │
│                                                      │
│   不是 "顺序执行"                                    │
│   而是 "事件驱动" — 一切靠信号触发                     │
│                                                      │
│   按钮点击 ──► 信号 ──► 槽                             │
│   网络回包 ──► 信号 ──► 槽                             │
│   定时到点 ──► 信号 ──► 槽                             │
│   输入完成 ──► 信号 ──► 槽                             │
│                                                      │
│   你写的槽函数，本质上就是"事件响应函数"                 │
└──────────────────────────────────────────────────────┘
```

**三板斧**：
1. 头文件：写 `Q_OBJECT`、`signals:` 声明信号（不实现）、`slots:` 声明槽（要写 `.cpp` 函数体）
2. `.cpp` 构造函数：用 `connect` 把信号和槽连起来
3. 需要通知时：`emit 信号名()`

**三种 connect 模式**：
- `connect(A, &A::sig, B, &B::slot)` — 信号→槽（跨对象）
- `connect(A, &A::sig, B, &B::sig)` — 信号→信号（转发）
- `connect(A, &A::sig, this, [this]{...})` — 信号→lambda（内联处理）

**项目架构**：
```
UI 层 (LoginDialog / RegisterDialog / ResetDialog)
  ↕ 信号槽
MainWindow (页面切换调度)
  ↕ 信号槽
HttpMgr (网络层，单例)
  ↕ QNetworkAccessManager
服务器
```
