# 开发日志

## 2026-07-06 配置 Redis / hiredis 依赖

### 问题现象

项目编译时报错：

```text
错误 C1083 无法打开包括文件: "hiredis.h": No such file or directory
```

报错位置出现在 `DistLock.h`、`DistLock.cpp`、`RedisMgr.h`、`StatusServer.cpp` 等使用 hiredis 的文件中。

### 原因分析

`hiredis.h` 并不是项目自身的头文件，而是 Redis C 客户端库 hiredis 提供的第三方头文件。虽然源码文件已经被添加到 Visual Studio 项目中，但这不代表第三方库的头文件目录和 `.lib` 链接目录已经配置好。

本机 vcpkg 中已经安装了：

```text
hiredis:x64-windows 1.3.0
```

实际头文件位置是：

```text
D:\cppsoft\vcpkg\vcpkg-master\installed\x64-windows\include\hiredis\hiredis.h
```

由于源码中使用了：

```cpp
#include <hiredis.h>
```

所以除了 vcpkg 的通用 include 目录，还需要额外加入：

```text
D:\cppsoft\vcpkg\vcpkg-master\installed\x64-windows\include\hiredis
```

否则编译器只能找到 `include`，但找不到顶层的 `hiredis.h`。

### 配置内容

新增属性表：

```text
vcpkg-redis.props
```

该属性表配置了：

```text
VcpkgRoot = D:\cppsoft\vcpkg\vcpkg-master
VcpkgTriplet = x64-windows
```

Debug / Release 共用的包含目录：

```text
$(VcpkgRoot)\installed\$(VcpkgTriplet)\include
$(VcpkgRoot)\installed\$(VcpkgTriplet)\include\hiredis
```

Debug 配置：

```text
库目录: $(VcpkgRoot)\installed\$(VcpkgTriplet)\debug\lib
链接库: hiredisd.lib; ws2_32.lib
运行库: $(VcpkgRoot)\installed\$(VcpkgTriplet)\debug\bin\hiredisd.dll
```

Release 配置：

```text
库目录: $(VcpkgRoot)\installed\$(VcpkgTriplet)\lib
链接库: hiredis.lib; ws2_32.lib
运行库: $(VcpkgRoot)\installed\$(VcpkgTriplet)\bin\hiredis.dll
```

同时在 `Project1.vcxproj` 中让 `Debug|x64` 和 `Release|x64` 自动导入：

```xml
<Import Project="vcpkg-redis.props" Condition="exists('vcpkg-redis.props')" />
```

另外新增 `vcpkg.json`，记录项目依赖：

```json
{
  "name": "project1-status-server",
  "version-string": "0.1.0",
  "dependencies": [
    "hiredis"
  ]
}
```

### 验证结果

使用 MSBuild 构建 `Debug|x64` 后，`hiredis.h` 找不到的问题已经消失。构建日志中可以看到 hiredis 头文件已经从 vcpkg 路径被正确读取：

```text
D:\cppsoft\vcpkg\vcpkg-master\installed\x64-windows\include\hiredis\sds.h
```

当前 Redis / hiredis 配置已经生效。

### 后续注意

当前配置只针对 `x64-windows`，因此 Visual Studio 中应选择：

```text
Debug x64
Release x64
```

不要选择 `Win32`。如果要编译 Win32，需要另外安装并配置：

```text
hiredis:x86-windows
```

本次 Redis 配置完成后，项目继续编译时出现的新错误已经不是 hiredis，而是 gRPC / protobuf 依赖未配置：

```text
grpcpp/grpcpp.h: No such file or directory
google/protobuf/port_def.inc: No such file or directory
```

这部分需要后续单独配置 gRPC 和 protobuf。

## 2026-07-06 修复 protobuf 版本不匹配和链接错误

### 问题现象

修复属性表导入后，项目继续编译时出现 protobuf 生成文件版本不匹配：

```text
message.pb.h: This file was generated by an older version of protoc
```

继续处理后又出现链接错误：

```text
LNK2019: 无法解析的外部符号 StatusServiceImpl::StatusServiceImpl
LNK2019: 无法解析的外部符号 sql::mysql::_get_driver_instance_by_name
LNK2019: 无法解析的外部符号 check(...)
```

### 原因分析

`message.pb.h/.cc` 原来是 protoc 3.13.0 生成的，但当前 `GrpcDebugSheet.props` 使用的是 `D:\cppsoft\grpc` 下的 protobuf 3.21.6 头文件和库。protobuf 会在生成文件中检查版本，因此旧生成文件会被当前头文件拒绝。

链接错误分成两类：

1. `StatusServiceImpl.cpp` 没有加入 `Project1.vcxproj` 的编译项，导致构造函数等实现没有参与链接。
2. MySQL connector 的头文件和库目录虽然配置了一部分，但 Debug 链接项里没有加入 `mysqlcppconn.lib` 和 `mysqlcppconn8.lib`，导致 MySQL connector 符号无法解析。

### 处理方式

使用当前 gRPC/protobuf 对应的工具重新生成 proto 文件：

```powershell
D:\cppsoft\grpc\visualpro\third_party\protobuf\Debug\protoc.exe `
  -I D:\qtstudy\llfcchat\server\StatusServer `
  --cpp_out=D:\qtstudy\llfcchat\server\StatusServer `
  --grpc_out=D:\qtstudy\llfcchat\server\StatusServer `
  --plugin=protoc-gen-grpc=D:\cppsoft\grpc\visualpro\Debug\grpc_cpp_plugin.exe `
  D:\qtstudy\llfcchat\server\StatusServer\message.proto
```

重新生成后，同步以下文件到当前 `Project1` 目录，避免本地双引号 include 优先包含旧副本：

```text
message.proto
message.pb.h
message.pb.cc
message.grpc.pb.h
message.grpc.pb.cc
```

在 `Project1.vcxproj` 中加入缺失的源文件：

```xml
<ClCompile Include="..\..\..\llfcchat\server\StatusServer\StatusServiceImpl.cpp" />
```

并同步更新 `Project1.vcxproj.filters`，让它在 Visual Studio 的“源文件”分组中显示。

在 `GrpcDebugSheet.props` 中补充 MySQL connector Debug 链接配置：

```text
AdditionalLibraryDirectories:
D:\cppsoft\mysql-connector\mysql-connector-c++-8.3.0-winx64\lib64\vs14
D:\cppsoft\mysql-connector\mysql-connector-c++-8.3.0-winx64\lib64\vs14\debug

AdditionalDependencies:
mysqlcppconn.lib
mysqlcppconn8.lib
```

同时在 `Project1.vcxproj` 中增加 Debug x64 构建后的运行时 DLL 复制目标：

```text
mysqlcppconn-9-vs14.dll
mysqlcppconn8-2-vs14.dll
libcrypto-3-x64.dll
libssl-3-x64.dll
```

这些文件会被复制到：

```text
x64\Debug
```

### 验证结果

执行完整重新生成：

```powershell
MSBuild .\Project1.vcxproj /t:Rebuild /p:Configuration=Debug /p:Platform=x64 /m /v:minimal
```

结果成功生成：

```text
D:\qtstudy\server\StatusServer\Project1\x64\Debug\Project1.exe
```

当前已解决的错误：

```text
C1083 hiredis.h 找不到
MSB4019 PropertySheet.props 导入失败
C1189 protobuf 生成文件版本不匹配
LNK2019 StatusServiceImpl 未链接
LNK2019 MySQL connector 符号未解析
```
